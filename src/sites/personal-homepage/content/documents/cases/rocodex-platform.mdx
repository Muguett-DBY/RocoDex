<ArchiveSection id="problem" title="共享部署不等于共享产品。" eyebrow="01 / 问题">

个人主站 custard.top 与 RocoDex 图鉴拥有不同用户、路由和运行时需求。最危险的方案不是放在一起，而是边界只存在于口头约定。

- 主站不应初始化图鉴的认证上下文。
- 错误域名不能泄露另一站页面。
- 每站都要有自己的浏览器回归与 SEO 输出。

</ArchiveSection>

<ArchiveSection id="architecture" title="Host 决策先于页面渲染。" eyebrow="02 / 架构">

Proxy 先按 Host 决定重写、跳转、放行或 404；Next route group 再表达页面所有权；站点模块通过极小 public API 暴露给路由适配器。

<CodeSample language="text" label="请求链路">

```text
request
  -> host decision
  -> route group
  -> site public API
  -> isolated product tree
```

</CodeSample>

</ArchiveSection>

<ArchiveSection id="decision" title="用测试守住目录无法守住的边界。" eyebrow="03 / 决策">

架构测试扫描生产代码导入关系，禁止个人主站越界使用 RocoDex 模块，也限制 Three.js 运行时只出现在延迟场景中。

</ArchiveSection>

</LocaleBlock>

<LocaleBlock locale="en">

<ArchiveSection id="problem" title="A shared deployment is not a shared product." eyebrow="01 / Problem">

custard.top and RocoDex serve different audiences with different routes and runtime needs. Co-location was not the risk; undocumented ownership was.

- The portfolio must not initialize the encyclopedia auth context.
- The wrong host must never expose pages owned by the other product.
- Each site needs its own browser regression and SEO output.

</ArchiveSection>

<ArchiveSection id="architecture" title="Host decisions happen before rendering." eyebrow="02 / Architecture">

The proxy chooses rewrite, redirect, pass-through, or 404 by host. Route groups then express ownership, while each site exposes only a narrow public API.

<CodeSample language="text" label="Request path">

```text
request
  -> host decision
  -> route group
  -> site public API
  -> isolated product tree
```

</CodeSample>

</ArchiveSection>

<ArchiveSection id="decision" title="Tests enforce what folders alone cannot." eyebrow="03 / Decision">

Architecture tests scan production imports, block cross-site dependencies, and keep the Three.js runtime confined to its lazy scene boundary.

</ArchiveSection>

</LocaleBlock>
