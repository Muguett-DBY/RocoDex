<ArchiveSection id="problem" title="研究质量取决于证据寿命，而不是回答长度。" eyebrow="01 / 问题">

行情、财务、公告和行业线索更新频率不同。把抓取、综合与页面请求绑在一起，会同时得到超时、重复成本和不可追溯结论。

我不想再做一个“问一句就给一篇报告”的页面。研究真正需要的是把问题拆成几个可以回看的决定：这家公司是谁，数据来自哪里，哪些字段还缺，估值用的是什么假设，什么证据会让结论失效。报告只是这串决定最后被整理出来的一个版本。

</ArchiveSection>

<ArchiveSection id="pipeline" title="先生成证据指纹，再决定是否调用模型。" eyebrow="02 / 管线">

定时 Action 负责收集和归一化公开数据；Pages Function 只创建或复用任务；后台工作流完成深度综合并写回 D1/R2。证据没有实质变化时复用缓存。

这样分层还有一个实际好处：某一环失败时，不会把所有状态都说成失败。抓取失败可以保留上一次有时间戳的资料，模型调用失败可以重试综合，发布失败也不会抹掉已经生成的版本。用户看到的不只是一个 loading，而是当前研究到底走到了哪一步。

<CodeSample language="text" label="异步研究链">

```text
collect -> normalize -> fingerprint
        -> queue -> synthesize -> publish
        -> version -> review
```

</CodeSample>

</ArchiveSection>

<ArchiveSection id="valuation" title="确定性公式拥有最终决定权。" eyebrow="03 / 估值">

五年 FCFF DCF 在浏览器预览和服务端保存中使用同一套公式。AI 只解释假设，不直接修改最终计算；每次保存创建不可变后继版本。

版本不可变是为了让复盘有对象可指。下一次研究可以基于新证据建立后继版本，但不会改写旧报告的输入。遇到争议时，可以先比较两个版本的证据和假设，再讨论结论，而不是凭印象回忆模型当时说了什么。

</ArchiveSection>

</LocaleBlock>

<LocaleBlock locale="en">

<ArchiveSection id="problem" title="Research quality depends on evidence freshness, not answer length." eyebrow="01 / Problem">

Prices, filings, disclosures, and industry signals age at different rates. Binding collection and synthesis to a page request creates timeouts, repeated cost, and untraceable conclusions.

I did not want another page that answers one prompt with one report. Research needs a series of decisions that can be revisited: which company is this, where did the data come from, what is missing, which assumptions drive the valuation, and what evidence would disprove it. The report is one version of that chain, not the whole product.

</ArchiveSection>

<ArchiveSection id="pipeline" title="Fingerprint evidence before invoking a model." eyebrow="02 / Pipeline">

Scheduled Actions collect and normalize public data. Pages Functions create or reuse jobs; background workflows synthesize and persist to D1/R2. Unchanged evidence reuses cached work.

The separation has a practical benefit: one failed stage does not make every state look failed. Collection can keep the last dated material, synthesis can retry without fetching everything again, and publication does not erase a version that already exists. The user sees where the research stopped instead of one permanent loading state.

<CodeSample language="text" label="Asynchronous research chain">

```text
collect -> normalize -> fingerprint
        -> queue -> synthesize -> publish
        -> version -> review
```

</CodeSample>

</ArchiveSection>

<ArchiveSection id="valuation" title="Deterministic formulas retain final authority." eyebrow="03 / Valuation">

The five-year FCFF DCF uses the same deterministic formula in browser preview and server persistence. AI explains assumptions but cannot decide outputs; every save creates an immutable successor.

Immutable versions give review something concrete to point at. A new run can build a successor from new evidence without rewriting the old inputs. When two results disagree, compare their evidence and assumptions before debating what the model “meant”.

</ArchiveSection>
