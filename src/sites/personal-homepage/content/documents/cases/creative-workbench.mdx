<ArchiveSection id="model" title="创作不是一个输入框。" eyebrow="01 / 模型">

对话会分支，生成会排队，素材会回溯到提示词。系统因此围绕可恢复的会话、任务与资产实体设计，而不是围绕一个聊天组件。

我不希望创作过程被压扁成“输入一次，等一个答案”。一个想法往往要经过几次改写、参考图和方向分叉，最后才知道哪一条值得留下。会话保存上下文，分支保存试错，资产保存结果和来源，这三个对象分开之后，用户才有机会回到某个决定之前重新走一遍。

</ArchiveSection>

<ArchiveSection id="media" title="元数据走 D1，大对象走 R2。" eyebrow="02 / 媒体">

图片和视频任务保留状态、尺寸、种子和错误；素材上传检查 Magic Bytes；界面轮询有失败上限，避免永远旋转的任务。

这些细节看似偏后台，却会直接影响创作体验。生成失败时，用户需要看到失败发生在哪一步，而不是把一个加载圈留到第二天；刷新页面后，已经完成的素材也应该能被找回来。D1 和 R2 的分工，最终要在这种日常操作里体现出来。

</ArchiveSection>

<ArchiveSection id="safety" title="私人系统也需要明确的滥用边界。" eyebrow="03 / 安全">

登录指数退避、API 分级限流、Secure Cookie、401 自动退出和内容类型校验共同缩小攻击面。

私人并不等于可以省略边界。上传、生成和导出都会消耗资源，失败重试也可能放大成本。把身份、额度、文件类型和任务状态分别写清楚，既保护系统，也让使用者知道为什么某个动作需要等待或确认。

</ArchiveSection>

</LocaleBlock>

<LocaleBlock locale="en">

<ArchiveSection id="model" title="Creation is more than one prompt box." eyebrow="01 / Model">

Conversations branch, generations queue, and assets trace back to prompts. The system is modeled around recoverable sessions, jobs, and assets rather than a single chat component.

I did not want the creative process reduced to “enter once, wait for an answer”. An idea usually passes through rewrites, reference images, and divergent directions before one path earns a place. Conversations keep context, branches keep experiments, and assets keep results and provenance; separating them lets someone return to an earlier decision and try again.

</ArchiveSection>

<ArchiveSection id="media" title="Metadata goes to D1; large objects go to R2." eyebrow="02 / Media">

Image and video jobs retain status, dimensions, seed, and errors. Uploads inspect magic bytes, while bounded polling prevents permanently spinning jobs.

These backend details shape the daily experience. When generation fails, the user should see which step failed instead of an endless spinner; after a refresh, completed assets should still be there. The D1/R2 split matters only when it makes those ordinary actions dependable.

</ArchiveSection>

<ArchiveSection id="safety" title="Private tools still need abuse boundaries." eyebrow="03 / Security">

Login backoff, endpoint-specific rate limits, secure cookies, automatic 401 logout, and content validation reduce the attack surface.

Private does not mean that boundaries can be skipped. Uploads, generations, and exports consume resources, and retries can multiply the cost. Separating identity, limits, file types, and job state protects the system while explaining why an action must wait or be confirmed.

</ArchiveSection>
