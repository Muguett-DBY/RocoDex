# CSTD Comparison Context Design

Stage 4 made the workflow summary navigable, and Stage 5 made deep links restore without showing the wrong default state. The final improvement should make the destination itself more self-contained: when a visitor lands directly on the comparison matrix, the matrix header should carry the active goal and the selected project names.

## Goal

Make `#project-comparison` understandable as a standalone decision surface without changing the URL-state contract or adding another broad homepage section.

## Behavior

- When a goal is selected, the comparison header shows the current goal path.
- The header also shows the selected project titles in comparison order.
- Without a selected goal, the header still explains that the comparison is using manually selected projects.
- The copy is generated by a pure helper so the visible contract is tested outside the large client component.

## Validation

- Unit tests cover goal-backed and manual comparison contexts.
- Browser QA verifies a direct deep link on desktop and 390px mobile shows the new context, keeps the next action working, has no horizontal overflow, and has no console warnings/errors.
